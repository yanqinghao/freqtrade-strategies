# 限价单有效期与止损落地确认

用户已确认：新限价单默认4小时有效，可用 ttl=1h、ttl=1d 覆盖；既有挂单不追溯设置 TTL。助手管理的限价入场单检测到部分成交后，撤销未成交余量，优先把成交数量纳入原生持仓与止损管理。

采用交易主循环内的撤单/核对流程，复用官方 Freqtrade 2026.10 的订单查询、取消、成交记账与止损处理；独立 watchdog 仍然只通知，没有交易权限。不维护框架分叉，不另建独立下单服务。

## 限价单生命周期

- TG 的新限价开仓/加仓默认 ttl=4h；支持整数分钟/小时/天，范围1分钟至5天（当前原生全局超时上限）。市价单不能填写 ttl。
- TTL 作为每笔入场订单的持久化标签元数据保存，按交易所原始 order_date 计算；重启、修改计划不会续期。旧订单无 TTL 标签，继续沿用原超时。
- 检测到部分成交，或带 TTL 的限价单已到期，先查询该订单最新状态，再只撤剩余未成交量。取消结果必须确认，不能把超时/查询失败当作撤单成功。
- 部分成交的最终回执通过原生 update_trade_state 记账；不绕回“保留小额未成交单继续凑仓”的路径，不自动补仓。已全部成交则按成交处理，不宣称已撤单。
- 仅在确认零成交取消后才走原生空单清理；原有已成交仓位与计划继续保留。计划清理须校验 trade_id，不能删掉同币种后来的新计划。
- 程序端 TTL 依赖机器人在线及网络可用，无法保证停机/断网时准点撤单；保留守护告警。只处理助手数据库中已跟踪的手动入场订单，不触碰外部挂单或止损/退出订单。

## 止损落地确认

- 只对已成交且仍有数量的助手仓位核验，给原生下一轮创建止损的机会；首次成交15秒内为待确认，期间不能加仓。之后持续未确认则告警，恢复/实际保护变化时通知，重复相同异常不刷屏。
- 定期（正常30秒，待确认15秒）读取原生跟踪的交易所止损订单，核对实时回执的 ID/交易对、活跃状态、平仓方向、只减仓/整仓关闭标志、触发价及覆盖数量。不能只凭本地存在一条止损记录宣称受保护。
- 实际触发价不得比当前 SL/移动保护目标更宽松；覆盖量须足够，只减仓订单覆盖量大于剩余仓位可接受。closePosition 整仓止损可按整仓覆盖处理。按官方规范化后的基础币数量核对，不能重复乘 contractSize。
- 已触发/已结束/已取消、数量不足、价格待更新、字段不完整及接口失败分别视为未确认或退出处理中，不能报“已保护”。不会新增独立强平逻辑，保留原生现有止损恢复及紧急退出机制。
- 每次加仓前再强制实时核验保护，失败则在修改计划/提交订单前拒绝；初次开仓仍要求 sl。退出、止盈和强制平仓不受保护校验阻塞。模拟模式不查询真实账户，也不冒称交易所已确认。
- 保护状态与通知指纹持久保存在现有交易自定义数据中；通知包含实际止损价、覆盖量与核验时间。辅助模块与入口使用顶层导入，避免原生临时路径移除后加载失败。

## 验证与上线

先写离线测试，覆盖 TTL 参数、到期/重启/旧单、部分成交及小额成交、撤单竞态和未知回执；覆盖多空、覆盖量/只减仓/触发价、查询失败、状态去重、加仓阻断及退出不受影响，包含官方原生记账集成。完整回归后独立审查，提交推送，备份并核对线上记录再更新服务；不提交测试订单、不人为制造真实故障。
