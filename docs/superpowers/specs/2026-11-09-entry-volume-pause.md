# 原挂单逆向放量暂停与原价恢复：测试后规则建议

更新日期：2026-11-09。状态：**已按用户授权提交、推送并部署；北京时间2026-11-09 15:38恢复RUNNING**。
此前放量直接永久取消方案已撤回。本次仅实现已确认的原挂单暂停与原价恢复。

## 目的和方案取舍

减少原未成交限价单在极端逆向行情中继续接入的部分损失，不以规避所有亏损为目标。
用户明确只使用自己事先给出的原挂单点位。原入场价E、方向、硬SL S、软SL、三档TP及有效期
来自该计划；R=abs(E-S)，在该计划版本创建时确定。不使用后来才出现的点位。

比较过三种方案：异常即永久取消违背用户要求；附近市价恢复可能提前接入下一轮下跌；
暂停后恢复原价限价在本批样本较少亏损，因此推荐第三种，不能宣称已经稳定盈利。

## 候选默认规则

1. 只作用于BTC/ETH原初始限价计划。没有原计划时只监控、提示，不自主开仓。
   未遇异常的限价单继续原流程，不额外要求突破、强实体、同向10倍放量或收回确认。
2. 当前形成中5m的实际累计基础币量，除以前24根完整5m均量，达到4倍且逆向时暂停。
   做多看最新价低于该5m开盘，做空相反。不能按分钟进度外推成交量，不等整个5m收盘。
   监控整个挂单有效期，不等接近原入场价才识别远处已经开始的冲击。
3. 每次已知逆向放量观测更新last_adverse。最近15分钟没有新异常才允许考虑恢复；
   告警去重不能阻止风控计时刷新。4倍/15分钟是候选默认，不是普适最优参数。
4. 放量只临时暂停。等待期间触及原硬SL（多<=S，空>=S）才因价格永久失效；用实际高低价，
   不能只看收盘。原TTL到期、用户取消或明确新计划替换同样结束计划，反弹不能使它复活。
   系统风控撤掉交易所订单与用户取消计划必须区分。暂停、恢复、重启都不延长TTL。
5. 多单恢复要求最近完整1m收盘C、当前可成交参考价Q都接近原入场价：
   `max(abs(C-E), abs(Q-E)) <= 0.25 * R`。
   0.25R只是保守提议；原价恢复的0.25R/0.5R在这39条请求中结果相同，没有优劣证据。
   2026-11-09用户确认调整：空单取消¼R门槛，未涨过E时安静15分钟后即可恢复原价限价；
   涨过E仍须满足第6条完整1m收回及当前价收回。多单规则不变。此调整尚未部署。
6. 若暂停期间穿过E，必须由穿越之后的完整1m收盘收回：多C>=E，空C<=E；当前价也在收回侧。
   不能使用穿越前的旧收盘。当前报价刚刚首次穿过E时，同样先等收回。
7. 恢复动作仅为**原方向、原价E限价挂回**，不在范围内提前市价成交，不提高买价或压低卖价。
   保留原绝对SL/TP，不因等待平移。用户后续明确改单独立处理，不按历史中位数重设原计划。
8. 恢复后再次逆向放量，继续暂停尚未成交订单。仅远离恢复范围不单独触发反复撤挂。
   范围是被暂停计划的恢复门槛，不是所有正常订单的额外门槛。
9. 已成交或部分成交转原持仓/退出管理，不反手、不重复补回，不把事后撤单当作撤销已成交。
   软SL仍按原收盘规则管理持仓，不当作未成交计划已触硬SL的证据。

不启用自主追单、自动反手、放量即永久取消、原单全部TP减半，或BTC1.2%/ETH1.8%振幅主过滤。
回测使用BTC20U/ETH10U保证金、20倍；研究口径本身不自动修改实盘请求金额或风险上限。

## 状态与执行边界

状态路径：原价挂单→撤单确认中→暂停观察→恢复提交中→原价挂单。
已成交、触SL失效、到期、用户取消/明确替换为终态；回执不明为待核查，禁止自动重发。

- 仅最终确认零成交的初始限价计划可自动恢复；先确认旧单终结、清理并核实最终成交量。
- 保存计划ID/版本、原TTL/E/S/TP、订单ID、暂停原因、last_adverse、穿越时间、SL历史检查进度与恢复回执。
- 恢复复用请求去重、仓位、挂单、敞口、止损风险和最终出站检查；旧消息不产生新计划。
- 公共行情采集可在工作线程，撤挂由现有串行执行路径处理，不在工作线程直接交易或阻塞退出。
- 行情过期、缺口、重启历史不足时不恢复；不能把缺口当成安静15分钟或没有触SL。
- 创建所在分钟极值若前后顺序不明，等待可靠证据，不凭整根极值推断创建后已经触SL。
- /stopentry或/stop期间不得恢复，原TTL继续；暂停计划可以查询、主动取消。
- 新状态通知用北京时间，明确区分临时暂停、恢复原价挂单、触SL永久失效。
- 本计划已失效后，扩大SL不能自动复活旧计划；用户新的价位须明确为新版本并重新核验。

回测按已完成1m逐步观察形成中5m量；实盘可更频繁使用已发生行情尽早暂停，但未证明收益等同。
回测用分钟开盘加不利滑点近似Q，真实报价不同，需记录验证。分钟回放假定及时撤单，不能保证实盘先于撮合。
