# Telegram 订单管理

用户要求在 Telegram 查看挂单和持仓，点击详情实时刷新，点字段修改 TP/SL/收盘软止损/延伸规则，快速平仓；用户明确确认未成交挂单也要修改开仓价。

采用现有 Telegram 原生 inline buttons + ForceReply，复用交易线程命令队列、原生 RPC、风险检查和请求账本。不另建网页或服务。保留旧文本命令，/orders 与 /status table 打开管理列表。

列表按挂单/持仓筛选并分页。详情显示方向、数量、挂单价/实际成交价、最新参考价和更新时间、止盈进度、配置 SL 与有效保护价、软止损与延伸条件。每页有刷新和返回。交易所查询失败明确标记，禁用修改和交易按钮，仍可返回刷新。

点击单字段，回复数值；新建软止损/延伸规则逐步填写，完整后原子保存。已完成 TP 档不可改，未完成 TP 修改保留成交进度；有退出单在途或延伸已激活时阻止不兼容修改。实际成交价不可修改。

修改挂单价要再次确认：仅限初始限价单且零成交，重新核对交易所后撤旧单，收到确认零成交终态才重新下单。维持保证金/杠杆和原截止时间，复用风险检查；任何部分成交或未知回执均停止重挂。请求账本持久防重；撤成但新单拒绝时明确告知。

快速全平/撤单需显示对象与数量后二次确认。所有操作使用原授权检查，并绑定用户/聊天/topic/提示消息，过期和状态冲突要求刷新；不以成功提示代替真实提交/成交确认。所有外部写入仅在用户按钮确认/回复后发生。

验收涵盖长短单、空列表、分页、刷新失败、旧按钮、不同用户回复、重复确认、TP 阶段保留、改单成交竞态、撤单未知、原截止时间与正常风险门禁。仅离线模拟验证交易动作，不用实盘订单试点按钮。
