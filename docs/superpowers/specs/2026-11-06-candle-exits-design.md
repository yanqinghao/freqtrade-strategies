# 收盘软止损与 TP3 延伸

用户已在对话中确认以下规则。采用现有手动计划、原生成交记账和退出流程，不引入依赖，不自动开仓。

## 行为

- 可选 `soft_sl=<价> soft_tf=4h`：空单收盘价 >= soft_sl、多单 <= soft_sl 时全平剩余仓位。`sl` 仍是必填的即时硬止损，风险预览仍按硬止损估算。
- 可选 `extend_trigger=<价> extend_tp3=<价> extend_tf=4h`：仅三档 TP、TP2 已成交完成、原 TP3 尚未触发时，空单收盘价 <= trigger、多单 >= trigger，锁定延伸目标并把保护推进到 TP2。保护只收紧。
- 多单 TP2 < trigger < 原 TP3 < 延伸 TP3；空单相反。支持 15m、1h、4h、1d，周期与价格成组填写；不填写不改变旧行为。
- 原 TP3 在收盘确认前先触发时仍退出。已经开始原 TP3 退出（包括部分成交/撤单）不允许延伸。确认 K 线已经触及原 TP3 时也不延伸。
- 只用规则启用后、持仓建立后、且延伸需在 TP2 完成后新收盘的 K 线；不使用未收盘、过期或无效行情。重启保留已锁定状态。网络故障时原硬 SL/TP 继续有效。
- 软止损和保护止损优先于延伸。延伸后的 TP2 为即时保护，延伸 TP3 沿用原最终 TP 的成交处理。
- 已激活延伸不因价格回退或编辑计划而解除；其目标与 TP2 保护存入交易数据库。激活后拒绝修改 TP/延伸参数及加仓，避免重置阶段；仍可收紧 SL、修改未触发软 SL 和退出。
- `/setmanual`、开仓、预览、历史复制及 `/manual`、`/overview` 显示一致；允许 `soft_sl=off`、`extend_trigger=off` 关闭尚未触发规则，不能撤销已触发退出或延伸。

## 方案比较

用户选择保留原三档止盈，并以收盘条件切换 TP3 和 TP2 保护；不采用“TP3 到价后不平仓”的方案。复用 Freqtrade informative pairs 和行情缓存，不使用独立市场提醒线程下单。

## 实施约定

交易所原生 K 线周期（UTC 对齐）；收盘确认不保证按触发价成交。配置变更从当次新收盘开始，不追溯旧 K 线。旧交易未记录 TP2 时间时，首次检查建立基线，等待下一根收盘。数据恢复仅检查最新有效收盘，不重放停机期间所有信号。条件触发写入数据库，再通过现有原生退出/止损更新链路执行；交易所止损更新仍有原有间隔。

## 验证

覆盖多空、等号、未收盘/过期/无效数据、TP2 未完成、原 TP3 优先、软 SL 优先、重启锁定、只收紧、命令历史往返、无效计划拒绝、旧行为回归。不会修改生产配置或执行真实交易。
